# Генерация LLVM bitcode

Требуются C++20, CMake и пакет разработки LLVM версии 15 или новее.
Если CMake не находит LLVM, передайте путь к каталогу с
LLVMConfig.cmake через -DLLVM_DIR.

~~~sh
cmake -S . -B build
cmake --build build
./build/compiler tests/codegen.imp -o build/demo.bc
llc -filetype=obj -relocation-model=pic build/demo.bc -o build/demo.o
c++ build/demo.o -lm -o build/demo
./build/demo
./build/demo demo 3 2.5 1
ctest --test-dir build --output-on-failure
~~~

На Windows с MSYS2/UCRT64 используйте LLVM и C++ toolchain из одной
среды. В командах линковки и запуска укажите имя demo.exe.
Если Clang установлен, он также может скомпилировать и слинковать
биткод одной командой: clang build/demo.bc -lm -o build/demo.

Компилятор по умолчанию записывает .bc рядом с исходником. Флаг
--emit-llvm записывает текстовый .ll, а --dump-ast выводит
оптимизированное дерево. Опция -o задаёт путь к выходному файлу.
В обоих режимах LLVM проверяет модуль перед записью.

Полученный исполняемый файл принимает имя подпрограммы и её скалярные
аргументы. Для boolean в командной строке используются 0 и 1. Массивы
и записи передаются между подпрограммами внутри программы.
Без аргументов выбирается первая подходящая подпрограмма без параметров
в порядке main, test, затем первая по исходнику. Возвращаемое значение
стартовой подпрограммы отбрасывается, успешный запуск завершает процесс с кодом 0.

## Представление данных

- integer, real и boolean переводятся в i32, double и i1.
  Промежуточные значения получают уникальные имена SSA, присваиваемые
  переменные используют отдельные ячейки alloca, load и store.
- Условные операторы и циклы строят граф из базовых блоков с явными
  переходами. Вложенные Body создают свои области видимости.
- Массивы и записи передаются по ссылке. Дескриптор массива хранит
  длину и указатель на элементы. Индексация начинается с 1. Размер
  задаётся целочисленным константным выражением. Пропуск размера
  поддерживается у параметров, которые получают длину из аргумента.
  Свойство array.length доступно только для чтения.
  Разные именованные типы массивов сохраняют свою идентичность.
  Для массивов без имени сравниваются размер и тип элементов.
- Текущий runtime рассчитан на 64-битный C ABI. Объекты сохраняются до
  завершения процесса, чтобы возвращаемые и разделяемые ссылки оставались
  действительными. Память новых объектов обнуляется, вложенные
  ссылки можно заполнить присваиванием. Выход за границы массива,
  разыменование пустой ссылки и недопустимые числовые преобразования
  останавливают выполнение.

CTest сравнивает AST с golden-файлами. При наличии llc и совместимого
C++ линкера он также генерирует, компилирует и запускает биткод для
всех положительных тестов и проверяет фактический stdout.

Перевод выражений следует схеме рекурсивного отображения узлов AST из
лекции 9 (стр. 19–22). Типы, операции с памятью, SSA-значения, переходы
и инструмент llc соответствуют примерам лекции 12 (стр. 7–24).
Изменяемые переменные размещаются в памяти, поэтому их значения после
условного перехода считываются из общей ячейки.

## Где читать код

1. [generator.cpp](generator.cpp) обходит объявления и собирает текст модуля.
2. [function.cpp](function.cpp) хранит состояние одной функции, управляет
   областями видимости и формирует инструкции для работы с памятью.
3. [statement.cpp](statement.cpp) переводит блоки, присваивания, ветвления и циклы.
   [expression.cpp](expression.cpp) переводит выражения и преобразует значения.
4. [entry.cpp](entry.cpp) генерирует системную точку входа. Она выбирает
   подпрограмму Imp, разбирает аргументы и запускает её.
   [runtime_ir.h](runtime_ir.h) содержит готовый LLVM IR парсеров аргументов.
5. [bitcode.cpp](bitcode.cpp) разбирает и проверяет текст средствами LLVM,
   затем сериализует его в биткод.
