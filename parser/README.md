# Parser

Модуль синтаксического анализа. Принимает поток токенов от лексера, проверяет, что их
последовательность удовлетворяет грамматике языка, и строит абстрактное синтаксическое
дерево (AST). Реализован методом **рекурсивного спуска** (recursive descent).

## Состав модуля

| Файл | Назначение |
|------|-----------|
| `ast.h` | Узлы AST: иерархия C++-классов от базового `Node` |
| `parser.h` | Публичный интерфейс `IParser` и фабрика `makeParser` |
| `parser.cpp` | Реализация парсера |

Остальные модули видят только `parser.h`: класс `Parser` скрыт за фабрикой.

### `ast.h` — структура дерева

Каждый узел — одна конструкция языка. Базовый класс `Node` хранит `nodeType`
(тег для различения типов через `switch`) и `span` — позицию в исходном коде,
нужную для сообщений об ошибках на следующих этапах.

Основные группы узлов:

- **Выражения**: `IntegerLiteral`, `RealLiteral`, `BooleanLiteral`,
  `UnaryExpression`, `BinaryExpression`, `NameReference` (переменная),
  `MemberAccess` (`a.b`), `IndexAccess` (`a[i]`), `RoutineCall` (`f(x)`).
- **Типы**: `PrimitiveType` (`integer`, `real`, `boolean`), `NamedType`,
  `ArrayType`, `RecordType`.
- **Объявления**: `VariableDeclaration`, `TypeDeclaration`,
  `ParameterDeclaration`, `RoutineDeclaration`.
- **Операторы**: `Assignment`, `CallStatement`, `WhileLoop`, `ForLoop`,
  `IfStatement`, `PrintStatement`, `ReturnStatement`, а также `Body` —
  список элементов тела (рутина, цикл, ветка `if`).
- **`Program`** — корень дерева, список объявлений верхнего уровня.

Владение узлами — через `unique_ptr`: родитель живёт в стеке вызовов дольше
детей, поэтому память освобождается автоматически и без циклов.

### `parser.h` — интерфейс

```cpp
class IParser {
    virtual unique_ptr<Program> parseProgram() = 0;     // весь AST
    virtual const vector<string>& GetErrors() const = 0; // накопленные ошибки
};

unique_ptr<IParser> makeParser(vector<Token> tokens);
```

### `parser.cpp` — реализация

Класс `Parser` хранит вектор токенов, текущую позицию, список ошибок и
разбирает токены по принципу «одно правило грамматики — одна функция»:
`parseDeclaration`, `parseIfStatement`, `parseExpression` и т.д.

## Flow синтаксического анализатора

1. Лексер превратил исходный текст в плоский список токенов.
2. Парсер читает токены слева направо и сверяет их с грамматикой.
3. Пока правило совпадает — попутно строится узел AST.
4. При несовпадении — синтаксическая ошибка: парсер сообщает о ней,
   пропускает токены до «безопасного места» и продолжает разбор
   (error recovery), а не падает на первой ошибке.
5. На выходе — корень `Program` и список ошибок. Семантический анализ
   дальше ходит по дереву и проверяет типы и области видимости.

## Как строится дерево

Ключевая идея: **каждое правило грамматики = одна функция парсера,
каждый распознанный вызов = один узел дерева**. Дерево получается само
собой из вложенности вызовов: стек вызовов повторяет структуру
грамматики, а дети узла — результаты вызовов более «мелких» функций.

Пример для правила:

```
IfStatement → 'if' Expression 'then' Body ['else' Body] 'end'
```

```cpp
StatementPtr parseIfStatement() {
    Token start = expect(tokenIf);                // 1. требуем 'if'
    ExpressionPtr condition = parseExpression();  // 2. ребёнок "условие"
    expect(tokenThen);                            // 3. требуем 'then'
    BodyPtr thenBody = parseBody();               // 4. ребёнок "then-ветка"
    BodyPtr elseBody;
    if (match(tokenElse)) {                       // 5. 'else' необязателен
        elseBody = parseBody();                   // 6. ребёнок "else-ветка"
    }
    expect(tokenEnd);                             // 7. требуем 'end'
    return make_unique<IfStatement>(..., std::move(condition),
        std::move(thenBody), std::move(elseBody));
}
```

- **Рекурсия вниз = спуск по дереву.** Функция вызывает более мелкие
  функции парсера; каждая возвращает готовый подузел.
- **Возврат вверх = склейка узла.** Когда все дети распознаны, функция
  создаёт свой узел через `make_unique` и кладёт в него подузлы детей
  через `move`.
- **`match` vs `expect`** — обязательность части правила. `expect(code)`:
  токен обязан быть, иначе ошибка. `match(code)`: токен опционален,
  если есть — съесть.

Дерево для `x := a + b * 2`:

```
Assignment
├── target: NameReference "x"
└── value: BinaryExpression (+)
    ├── left:  NameReference "a"
    └── right: BinaryExpression (*)
        ├── left:  NameReference "b"
        └── right: IntegerLiteral 2
```

### Приоритеты операций — форма дерева

Лестница функций парсера от низшего приоритета к высшему:

```
parseExpression  → and / or / xor
parseRelation    → <  <=  >  >=  =  !=   (по одному сравнению)
parseSimple      → +  -
parseFactor      → *  /  %
parseSummand     → скобки
parsePrimary     → литералы, not, унарный знак, имена, вызовы
```

`parseFactor` (для `*`) вызывается глубже, чем `parseSimple` (для `+`),
поэтому `*` связывает операнды «теснее» и оказывается ниже в дереве —
то есть вычисляется раньше. Скобки в приоритет не попадают:
`parseSummand` возвращает внутреннее выражение как есть, поэтому
`(a + b) * 2` даёт дерево, где `+` стоит ниже `*`.

### Левая ассоциативность — цикл

`a - b - c` разбирается как `(a - b) - c`: каждая итерация цикла
заворачивает накопленный `left` в новый узел, получается «лестница»,
наклонённая влево.

```cpp
ExpressionPtr parseSimple() {
    ExpressionPtr left = parseFactor();
    while (check(tokenPlus) || check(tokenMinus)) {
        Token op = advance();
        left = make_unique<BinaryExpression>(op.code, std::move(left), parseFactor());
    }
    return left;
}
```

## Обработка ошибок

Парсер не останавливается на первой ошибке:

- `report()` добавляет сообщение в `errors`, но не более одной ошибки на
  строку (`lastErrorLine`), чтобы не засыпать пользователя повторами.
- `error()` сообщает и бросает `SyntaxError`.
- `parseSequence()` — центральный цикл: ловит `SyntaxError`, вызывает
  `synchronize()` (проматывает токены до конца строки, `;`, `end` или
  `else`) и продолжает разбор следующего элемента. Если `synchronize`
  ничего не промотал — сдвиг на один токен, защита от зависания.
- Токены `newline` и `;` — взаимозаменяемые разделители
  (`skipSeparators`). После каждого элемента `parseSequence` требует
  разделитель, поэтому `var a is 1 var b is 2` без перевода строки —
  ошибка.

На выходе — полностью построенный `Program` (насколько удалось
восстановиться) и список человекочитаемых ошибок с указанием строки и
колонки.

## Особенности языка

- Рутины: параметры в скобках, необязательный тип результата после `:`,
  тело либо `is ... end`, либо expression-body `-> выражение`.
- `return` разрешён только внутри рутины с объявленным типом результата
  (флаг `insideTypedRoutine`) — проверка выполняется на этапе парсинга.
- `parseAssignmentOrCall` разрешает неоднозначность после идентификатора:
  присваивание, вызов или доступ к полю/индексу (`a.b[i] := v`).
- `parseAccessors` в цикле навешивает цепочки `.поле` и `[индекс]`.
- Вложенные рутины распознаются, но помечаются ошибкой
  «Nested routine declarations are not supported».

## Почему рекурсивный спуск

Парсер не строит таблицы состояний (как yacc/bison). Вместо этого для
каждого нетерминала грамматики пишется своя функция на C++, и разбор —
это просто вызов `parseProgram()`, который рекурсивно вызывает остальные.

Плюсы: код читается как грамматика, легко вставлять свою обработку ошибок
и свои узлы AST. Минус: для больших языков парсер разрастается, поэтому
в индустрии часто используют генераторы (bison, ANTLR). Для учебного
проекта hand-written рекурсивный спуск — стандартный выбор.
